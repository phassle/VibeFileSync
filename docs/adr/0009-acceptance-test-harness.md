# Acceptance tests kill the real binary at instrumented transitions on hdiutil volumes and assert five named convergence invariants

Idea #1 made crash/fault-injection acceptance tests a spec requirement. This ADR fixes the harness design; the full enumerated matrix (every cell) lives on the deciding ticket and feeds the spec's acceptance-test section directly.

1. **Injection: test-only hooks in the real binary, real process death.** Gated behind a `fault-injection` cargo feature (never in release builds): `VIBESYNC_TEST_CRASH_AT=<transition>` makes the process `abort()` immediately after the named per-file transition; `VIBESYNC_TEST_EXEC_AT=<transition>:<command>` synchronously runs a shell command at the transition and continues — one generic hook covers source mutation, temp truncation/corruption, xattr stripping. In-process filesystem mocks were rejected as the matrix's definition — they never touch real APFS/exFAT semantics (rename behavior, kernel AppleDouble fallback, timestamp granularity), which is what the matrix exists to exercise; a mock-based unit layer remains an implementation freedom, not a spec requirement. **Documented limitation:** kill-based injection proves *ordering* correctness, not that `F_FULLFSYNC` defeats an actual power cut — true power-loss testing is hardware territory, out of scope for v1.
2. **Fixtures: suite-scoped `hdiutil` sparse images.** One APFS and one exFAT image attached per suite run, a fresh destination directory (and pair) per test case; ENOSPC cases get their own deliberately tiny dedicated images so filling them can't poison neighbors. The source side always lives on the Mac's native APFS. Images give each volume a real UUID (ADR-0002 identity tests reuse the same fixtures), need no root, and work on GitHub-hosted macOS runners. Pre-provisioned developer volumes were rejected (not reproducible, not CI-able); per-case images were rejected (attach/detach latency dominates the suite).
3. **Axes: destination filesystem × pipeline variant × crash transition.** Mode is *not* an axis — a replacement runs the identical archive→publish pipeline in Mirror and Update, and deletion exists only in Mirror — so mode is implied by the variant. Variants and their transitions: **new file** (6: temp created / copy complete / verify complete / source revalidated / Publish complete / `action_done` written), **replacement** (7: those plus old-version archived), **deletion** (2: archived / `action_done` written). (6+7+2) × {APFS, exFAT} = **30 crash cells**, plus one parity case asserting Update's replacement path behaves identically to Mirror's.
4. **Every cell asserts the same five named invariants**, checked twice — on the raw post-crash disk state and again after the convergence rerun: **I1** the old destination version is never lost (exists at its path or in `_SafetyNet/<run-id>/`, never neither); **I2** an unverified file is never published (a final path holds the old complete version or new gate-passed content, never a partial; temps only under temp names); **I3** one rerun converges (cleans and journals strays, fresh scan, exit 0, destination matches source per mode semantics); **I4** the records are honest (crashed run's journal is summary-less, `status` reports it interrupted, the rerun journals its cleanup — no crash yields a journal claiming success); **I5** the machinery stays invisible (`_SafetyNet/` and `.*.vibesync-tmp-*` never appear as sync content, are never copied as user data, and Mirror never deletes `_SafetyNet/`).
5. **Fault cases (via `EXEC_AT`, on the filesystem each is sensitive to):** source mutated mid-copy → `source_changed`; temp truncated → `verify_mismatch`, exit 1; xattr stripped on APFS → warning + publish, exit 0 (ADR-0008's split, both halves); one byte flipped mid-file → standard tier passes, `--verify` fails it; ENOSPC mid-run on a tiny image → clean abort, rerun converges; planted stray temps → `run` cleans and journals, `plan`/`status` only report; interrupted-run detection via summary-less journal; lock contention → exit 2, no destination writes. ADR-0002's precondition guards are deliberately excluded — ordinary functional tests, spec'd there.
6. **Home and gate:** `tests/acceptance/` drives the *built binary* (not library calls); invoked as `cargo test --features fault-injection --test acceptance` so plain `cargo test` stays fast and image-free. A GitHub Actions macOS job runs the full matrix on every PR into `develop` and `main` — merging a change that breaks a convergence invariant is impossible, not discouraged.

## Consequences

- The engine's per-file pipeline must expose the named transitions as instrumentation points; hook code is compiled out of release builds.
- The five invariants are the spec's testable definition of "crash-safe"; `/to-spec` copies the enumerated matrix from the ticket resolution into the spec.
- CI requires macOS runners with `hdiutil`; suite runtime (~30 crash cells + 8 fault cases, seconds each) fits a normal PR budget.
- Hardware power-loss testing is documented as out of v1 scope; `F_FULLFSYNC` correctness rests on the ordering protocol plus platform documentation.
