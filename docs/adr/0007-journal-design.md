# The Journal is a retained per-run NDJSON record that carries no safety invariant

The Journal design for v1:

1. **Role: record, not resume authority.** The full scan every run stays the single source of truth for what to copy; the Journal never overrides what the scan observes. Its jobs: detect an interrupted run, feed `status`/`history` (ADR-0004), and hold forensic detail. Journal-as-resume-authority was rejected — two sources of truth that drift the moment the destination changes between crash and rerun.
2. **Lifecycle: one journal file per run, retained.** The journal *is* the run record: `history` lists them, `status` reads the latest. A journal without a `summary` line is the permanent record of an interrupted run (the exit-code-4 state); nothing is ever appended after the owning run dies. A separate history store was rejected — the completion hand-off is itself a crash window.
3. **Format: NDJSON, schema `vibefilesync.journal/v1`**, sharing the run/v1 event vocabulary (`run_start` with the planned-action set, `action_start`, `action_done`/`failed`, `summary`), additive-only within `/v1` per ADR-0004. Journal entries may carry fields the stream omits (temp path, captured source identity). A torn final line is detectable and ignorable. SQLite was rejected (a dependency and a "database" for an append-only log); a bespoke compact format was rejected (a second parser for no v1 payoff).
4. **Location & Run id.** `~/Library/Application Support/VibeFileSync/runs/<pair-name>/<run-id>.ndjson` (state home per ADR-0006; pair-name keying means a renamed pair starts a fresh directory). The Run id is UTC ISO-8601 basic — `YYYYMMDDTHHMMSSZ` — one identity across the journal file name, the `_SafetyNet/<run-id>/` Run folder, and the `run_id` field in every JSON event. Basic format because exFAT forbids `:`; lexicographic order is chronological; UTC beats local time across DST/timezone moves; `-2`-style suffix on a same-second collision. Human surfaces render local time from the id.
5. **Temp convention: sibling dot-temps.** A copy is born as `.<name>.vibesync-tmp-<run-id>` in its final parent directory, so Publish is a same-directory rename with a single parent to fsync. The pattern embeds the run id, so any machine recognizes a stray without the journal (which lives on the Mac, not the destination volume). A staging directory at the destination root was rejected — it makes Publish a cross-directory rename for no structural gain. Temps are always excluded from scan/diff.
6. **Ordering & durability: the journal is deliberately cheap.** Per-file mapping: *pending* = listed in `run_start`; *in-progress* = `action_start`; *committed* = `action_done` written after Publish completes. There is no `archived` journal state — the `_SafetyNet` tree is its own durable record. Journal writes are buffered line appends with `fsync` at `run_start` and `summary` only; no `F_FULLFSYNC`. All safety invariants live in the destination-side protocol (temp fsync + `F_FULLFSYNC` + rename + parent-dir fsync); the worst a lost journal tail can cause is under-reported history.
7. **Restart reconciliation = cleanup + fresh scan, never replay.** The next real run of a pair deletes `.*.vibesync-tmp-*` strays during its scan (journaled and reported); `plan` and `status` are strictly read-only on the destination and only report strays. A crash between archive and publish needs no rule: the destination path is absent, the old version is in `_SafetyNet/<run-id>/`, and the rerun plans a fresh copy (ADR-0001's accepted window converging on its own).
8. **Locking: per-pair `flock`** on `runs/<pair-name>/.lock`. Mutating commands (`run`, `prune`) take it exclusively; contention is a fail-fast precondition abort (exit 2, "run already in progress") — no queueing. `flock` dies with the process, so a crashed run leaves no stale lock. Documented limitation: the lock lives on the Mac and cannot exclude a *different machine* writing the same destination volume.

Before the first v1 release, feature #14 used ADR-0004's explicit pre-release schema exception to finalize `journal/v1` with ADR-0008's structured `{code, detail}` warnings and the same normalized failure reason codes as `run/v1`. Acceptance tests freeze that final shape. No released consumer observed the earlier provisional string-warning/raw-reason form; additive-only compatibility applies from the first release onward.

## Consequences

- `status` and `history` parse journal files directly; `history --json` is nearly a pass-through of stored events.
- A lost, stale, or truncated journal can never endanger the destination — recovery never depends on it.
- Exit-code-4 "rerun resumes" means the rerun re-scans and converges; it does not replay the journal.
- The scanner must skip `.*.vibesync-tmp-*` and `_SafetyNet/` everywhere.
- The CLI inherits "run already in progress" as an exit-2 precondition (joins the ADR-0002 family).
