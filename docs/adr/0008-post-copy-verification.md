# Post-copy verification is a pre-archive gate: stat+xattr always, hash under --verify, data fails while metadata warns

`copyfile(3)` can return 0 while silently dropping metadata (research ticket [#3](https://github.com/phassle/VibeFileSync/issues/3): exFAT `fchown`/`fchmod` failures are ignored by design, ACL-apply is warn-only). The engine therefore never trusts the return code alone; this ADR defines the word **verified** in the glossary's Publish entry and the `verified` field ADR-0004 reserved on `action_done`.

1. **Default tier, every file: stat + xattr spot-check.** After `copyfile()` returns, re-`stat` the temp — size equals the source's, mtime applied within the destination's known timestamp granularity — and compare the temp's xattr names against the source's, filtered by what the destination filesystem is expected to preserve. A few syscalls per file, no data re-read. Trusting the return code was rejected (the ticket's premise); full read-back as the default was rejected (doubles destination I/O on every run for a corruption class that `F_FULLFSYNC` already makes rare).
2. **`--verify` per-run flag: full read-back.** Under `--verify`, the gate additionally re-reads *both* source and temp and compares hashes before Publish (which also strengthens source revalidation). Joins the per-run-flag family (ADR-0004); default off; suits "weekly cron passes `--verify`, daily doesn't". A standalone `verify <pair>` subcommand was rejected for v1 — verify-at-rest is an audit feature with its own diff semantics.
3. **Expected degradations are not mismatches.** The checker compares only what the destination filesystem can preserve, per the matrix from research #3 baked in per filesystem type. Degradations are a property of the Folder pair, so they surface **once per run**: a structured `degradations` list on `run_start` (codes such as `posix_permissions`, `acls`, `bsd_flags`, `timestamp_granularity`) plus one human preflight line. Per-file degradation notes were rejected as noise; silent/documentation-only was rejected — agents need the fact in-band. Symlink-on-exFAT stays what research #3 made it: a per-file **error** action in the plan, not a degradation.
4. **Mismatch consequences split by tier.** A **data** mismatch — size wrong, or hash wrong under `--verify` — fails the file: no Publish, temp deleted, `action_failed`, run continues, exit 1 (partial). A **metadata** mismatch — an xattr the destination should preserve is missing, mtime off beyond granularity — publishes anyway with a structured warning on `action_done`; a warnings-only run exits 0 with counts in `summary`. Uniform-fail was rejected (a deterministic metadata quirk would hold a file's data hostage forever); warn-only was rejected (verification without teeth). The resulting contract: `action_failed` always means "the destination does not hold this file's new version"; a warning always means "data landed, metadata imperfect".
5. **Placement: a single gate strictly before archive.** The per-file sequence becomes: write dot-temp → fsync + `F_FULLFSYNC` → **gate** (temp stat+xattr check, hash under `--verify`, source revalidation) → archive → Publish → journal commit. Any gate failure leaves the destination tree completely untouched for that file — no SafetyNet churn for a rejected copy. Source revalidation re-`stat`s the source against what the scan planned from (size + mtime); a changed source fails the file with the distinct reason `source_changed` — the temp is a copy of a moving target. No in-run retry: the next run's fresh scan converges (ADR-0007).
6. **JSON and journal contract (additive within `/v1`, per ADR-0004):** `action_done.verified` is the enum `"standard"` | `"full"` (tier that passed — an enum, not a boolean, so `--verify` runs are distinguishable and future tiers are additive); `action_done.warnings` is an array of `{code, detail}` entries, present only when non-empty; `action_failed.reason` gains `verify_mismatch` and `source_changed`; `run_start.degradations` as in point 3; `summary` gains a `warnings` count. The Journal carries the same vocabulary (ADR-0007), so `history` can answer "which runs had warnings".

## Consequences

- The glossary's Publish precondition ("a verified temp file") now has a concrete definition: the pre-archive gate of point 5.
- Agents branch on three cleanly separable signals: *failed* (new version absent), *warning* (data landed, metadata imperfect), *degradation* (known pair property, stated once).
- The acceptance-test matrix ticket ([#13](https://github.com/phassle/VibeFileSync/issues/13)) must cover: injected size mismatch, xattr drop on an APFS destination, hash mismatch under `--verify`, and source mutation mid-run.
- `--verify` roughly doubles read I/O for the run; documented, never the default.
- ADR-0004's per-run flag list gains `--verify`.

Decided on the wayfinder ticket [Decide post-copy verification: don't trust copyfile()'s return code](https://github.com/phassle/VibeFileSync/issues/11).
